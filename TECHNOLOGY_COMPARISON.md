## 1. Comparative Evaluation Across 13 Technical Domains

Each comparison evaluates viable candidates against AETHER FORGE's non-negotiable invariants (`INV-01`..`INV-05`: deterministic traceability, cryptographic worker boundary, plan-hash approval binding, empirical DAW qualification, and signed supply-chain integrity) rather than ecosystem hype.

| Domain | Candidates Evaluated | Decisive Technical Tradeoffs | Verdict & Selected Option |
|---|---|---|---|
| **1. Agent Orchestration** | **A.** Bounded Planner + `ToolManifest` DAG (`@aether-forge/provider-gateway`)<br>**B.** LangChain / LangGraph<br>**C.** AutoGen / CrewAI multi-agent chat | **B & C** introduce heavy transitive dependency trees, hidden prompt templates, and non-deterministic peer-agent chat loops that cannot be canonically hashed (`planHash`) before human approval. **A** emits a strict Zod-validated DAG of registered tools in `<200 LOC` with zero external framework dependencies. | **Select A:** Bounded Planner + Registered `ToolManifest` DAG ([ADR-0005](./docs/adr/0005-bounded-agent-roles.md)). |
| **2. LLM Provider Abstraction** | **A.** Internal `ProviderGatewayService` + `ServerSideSecretManager`<br>**B.** Direct vendor SDK calls per service<br>**C.** Client-side / worker-side LLM calls | **B** scatters redaction, budgeting, and prompt-version checks across services; **C** leaks API keys to untrusted browsers/workstations. **A** centralizes pre-egress credential/path redaction, SHA-256 prompt verification, and tenant quotas server-side. | **Select A:** Central `ProviderGatewayService` ([ADR-0006](./docs/adr/0006-provider-gateway-redaction-routing.md)). |
| **3. Tool Execution Protocol** | **A.** Declarative `ToolManifest` + OPA + Temporal + Signed `WorkerJob`<br>**B.** Direct LLM-to-MCP stdio/shell execution | **B** allows a prompt-injected model to invoke local tools immediately without durable approval state or cryptographic `planHash` binding. **A** preserves MCP-compatible tool schema descriptors while routing execution through OPA policy and signed worker grants. | **Select A:** Policy- and Approval-Mediated `ToolManifest` Execution ([ADR-0002](./docs/adr/0002-controlled-autonomy-policy-engine.md)). |
| **4. Durable Workflow Engine** | **A.** Temporal (`DurableTemporalOrchestrator`)<br>**B.** BullMQ / Redis queues<br>**C.** Stateless database cron polling | **B & C** lack deterministic workflow replay across long human approval waits (`30m`–`24h`), built-in compensation signals, and activity retry history correlation. **A** survives process restarts mid-approval and guarantees at-most-once side-effect execution. | **Select A:** Temporal Durable Orchestration ([ADR-0003](./docs/adr/0003-temporal-durable-orchestration.md)). |
| **5. Knowledge & Vector Substrate** | **A.** PostgreSQL 16 + `pgvector` + Immutable Object Store<br>**B.** Standalone vector DB (Pinecone/Qdrant/Milvus) only<br>**C.** Graph DB (Neo4j) | **B** splits metadata transactions from vector chunks, creating race conditions during tenant deletion propagation; **C** adds premature operational complexity. **A** enforces transactional `ON DELETE CASCADE` from `knowledge_sources` to `knowledge_chunks` and mandatory provenance citations. | **Select A:** PostgreSQL 16 + `pgvector` + Immutable Object Store ([ADR-0007](./docs/adr/0007-evidence-addressable-knowledge.md)). |
| **6. Contract & Schema System** | **A.** TypeScript + Zod v3 (`@aether-forge/contracts`) → Generated JSON Schema & OpenAPI 3.1<br>**B.** Protobuf / gRPC only<br>**C.** Unvalidated TypeScript interfaces | **C** evaporates at compile time, offering zero runtime protection at trust boundaries; **B** complicates browser UI forms and LLM structured JSON output validation. **A** validates at runtime and generates cross-language JSON Schema/OpenAPI artifacts from one source of truth. | **Select A:** Zod v1.0.0 Contracts + Generated JSON Schema & OpenAPI 3.1 ([ADR-0004](./docs/adr/0004-typed-protocol-first.md)). |
| **7. Policy Engine** | **A.** Open Policy Agent (OPA / Rego v1) signed bundles<br>**B.** Hardcoded `if/else` checks per controller<br>**C.** LLM-based safety judge | **C** is non-deterministic and vulnerable to second-order prompt injection; **B** cannot be version-pinned (`policyVersion`) or audited as a signed bundle digest (`bundleDigest`). **A** provides deterministic `allow \| requireApproval \| deny` with fail-closed bundle verification. | **Select A:** OPA Rego v1 Signed Policy Bundles ([ADR-0002](./docs/adr/0002-controlled-autonomy-policy-engine.md)). |
| **8. Local Workstation Worker** | **A.** Outbound-connected Windows Worker (`.NET 8` / Native C# `AetherForge.WindowsWorker.exe` + Node bridge)<br>**B.** Inbound SSH / Remote Desktop agent<br>**C.** Cloud-only container | **C** cannot access local FL Studio 2025 or private multi-GB stems; **B** opens a critical inbound attack surface on customer machines. **A** uses outbound-only mTLS, Windows OS DPAPI (`ProtectedData`), and local NTFS `FileAttributes.ReparsePoint` verification. | **Select A:** Outbound-Connected Windows Worker with DPAPI & Reparse-Point Guard ([ADR-0001](./docs/adr/0001-hybrid-control-plane.md)). |
| **9. Offline Audio DSP Engine** | **A.** Rust (`workers/audio-engine`) + Deterministic PCM16 WAV Engine (`@aether-forge/audio-engine`)<br>**B.** Browser Web Audio API<br>**C.** Running offline batch jobs inside the VST3 plugin thread | **B** lacks deterministic offline file batch quotas and native workstation access; **C** risks starving or crashing the host DAW audio thread. **A** isolates offline file processing with byte/duration/time quotas and atomic `.tmp-*` output. | **Select A:** Isolated Offline Audio Engine ([ADR-0008](./docs/adr/0008-local-audio-engine-separate-from-vst3.md)). |
| **10. Real-Time Audio Plugin** | **A.** C++20 Lock-Free Core (`AetherForgeRealtimeCore`) + CMake + JUCE / Steinberg VST3 SDK<br>**B.** Rust/WebAssembly audio plugin<br>**C.** Managed GC runtime (.NET / JS) in audio callback | **C** introduces garbage-collection pauses that cause audible dropouts; **B** has immature VST3 host compatibility across Windows DAWs. **A** guarantees `noexcept`, zero-allocation, lock-free `std::atomic` real-time execution. | **Select A:** C++20 Lock-Free Core + CMake + JUCE/VST3 SDK ([ADR-0008](./docs/adr/0008-local-audio-engine-separate-from-vst3.md)). |
| **11. DAW Integration (FL Studio 2025)** | **A.** Tier-Qualified Adapter (`inspect` via `.flp` `FLhd`/`FLdt` parser + Python controller script; `non_destructive_edit` via `.bak` staging)<br>**B.** Unconstrained mouse/keyboard UI macros<br>**C.** Undocumented binary `.flp` `FLdt` event patching | **B** breaks on window focus/DPI changes and risks destructive clicks; **C** corrupts proprietary third-party plugin states inside `.flp` files. **A** guarantees zero project corruption and fails closed on unqualified tiers (`INV-04`). | **Select A:** Tier-Qualified FL Studio 2025 Adapter ([ADR-0009](./docs/adr/0009-fl-studio-2025-qualification-layer.md)). |
| **12. Testing & Verification** | **A.** Vitest (`17` suites: contract, security, abuse-case, real Windows NTFS/DPAPI, HTTP E2E, performance) + `pluginval`<br>**B.** Mock-only unit tests | **B** fails to catch Windows path canonicalization, NTFS directory junction escapes, or real-time C++20 audio violations. **A** executes 52 tests including real Windows filesystem junctions and compiled `AetherForge.WindowsWorker.exe` DPAPI checks in `~1.8s`. | **Select A:** Multi-Layer Real-OS & Contract Verification Suite. |
| **13. Supply-Chain & Release Integrity** | **A.** CycloneDX 1.5 SBOM + SLSA v1.0 Provenance + Constant-Time Signature Check + Dual-Control Promotion<br>**B.** Unsigned CI zip artifacts with single-developer push | **B** permits tampered worker binaries or unauthorized production pushes. **A** enforces `Reviewer` ≠ `ReleaseManager` dual-control promotion (`INV-05`) and rehearsed rollback to prior signed versions. | **Select A:** Signed Artifact Registry with Dual-Control Promotion ([ADR-0010](./docs/adr/0010-release-integrity.md)). |
